# QR Code Generator

[![CI](https://github.com/mabra94/qrgen/actions/workflows/ci.yml/badge.svg)](https://github.com/mabra94/qrgen/actions/workflows/ci.yml)

A browser-only QR code generator. Everything — content, styling, and the optional
center logo — is generated locally in the browser. There is no backend, no
upload, and no telemetry, so the data you type never leaves your machine.

## Features

- **Content types:** Website URL, plain text, Wi-Fi, vCard, email, SMS, and phone.
- **Wi-Fi safety:** SSID/password fields are escaped so `;`, `,`, `\` and newlines
  cannot break the payload.
- **Design controls:** foreground/background colors, module shape, error-correction
  level, margin, and transparent background.
- **Center logo:** upload a PNG, JPEG, WebP, or SVG (max 2 MB). The file is read
  as a data URL in the browser and error correction is raised to `H` automatically.
- **Resizable logo:** a slider steps through the distinct sizes the QR format can
  actually draw. The cap is 50% of the error-correction recovery budget — a level
  chosen by exporting every size and decoding it, so the largest logo offered is
  one that still scans.
- **Scannability guardrails:** an error is raised when the foreground/background
  contrast falls below 4.5:1, and exporting is blocked until it is fixed.
- **Export:** download the result as PNG (512–4000 px) or SVG, with the four-module
  quiet zone the QR spec requires at every size.
- **Live preview:** the QR code re-renders as you type. New renders are built
  off-screen and swapped in atomically, so the preview never flashes or blanks.

## Privacy

All processing happens client-side. The only network requests are the initial
page load (the app bundle), and an end-to-end regression test asserts that QR
content and Wi-Fi credentials are never transmitted after that.

## Discoverability

The UI markup lives in `index.html`, not in JavaScript, so search engines and
crawlers that do not execute JavaScript (including most AI answer-engine bots)
see the real content. `index.html` also carries the title, description,
canonical URL, Open Graph tags and `WebApplication`/`FAQPage` JSON-LD, and
`public/` ships `robots.txt`, `sitemap.xml`, `llms.txt` and a favicon. Keep the
markup in `index.html` in sync when adding UI — `src/main.ts` only wires it up.
The Open Graph share image (`public/og.png`) is generated by `npm run og`, which
renders a real QR code with Playwright and verifies it still decodes.

## Prerequisites

- **Podman** (recommended, no local Node needed), or
- **Node.js 22+** and npm for local development.

## Quick start with Podman

```bash
podman compose up
```

Then open <http://127.0.0.1:5173>.

The compose service runs `npm install && npm run dev`, mounts the repository into
the container, and keeps `node_modules` in a named volume.

## Local development

```bash
npm install
npm run dev
```

Open <http://127.0.0.1:5173>. To run the browser tests locally, install the
browser once:

```bash
npx playwright install chromium
```

## Testing

| Command | What it does |
| --- | --- |
| `npm run typecheck` | TypeScript check (`tsc --noEmit`). |
| `npm run test:unit` | Vitest unit tests for payload generation and logo validation. |
| `npm run test:e2e` | Playwright browser tests against the dev server. |
| `npm run build` | Typecheck plus a production build into `dist/`. |
| `npm run check` | The full suite: typecheck → unit → build → end-to-end. |

Run everything with:

```bash
npm run check
```

### Full suite in a container

Everything above also runs inside a prebuilt Playwright image, so no host Node
install is needed:

```bash
podman build -t qr-code-generator-test -f Containerfile.test .
podman run --rm qr-code-generator-test
```

### Continuous integration

GitHub Actions runs `npm run check` on every push to `main` and on every pull
request targeting `main` (see [`.github/workflows/ci.yml`](./.github/workflows/ci.yml)).
On failure, the Playwright report and traces are uploaded as build artifacts.

### What the tests cover

- **Unit:** payload output for URL/Wi-Fi/vCard/email/text, control-character
  escaping, URL/email/phone validation, logo type/size validation, WCAG contrast
  maths, the quiet zone, and the drawable logo sizes per error-correction level —
  checked against widths measured from `qr-code-styling` itself.
- **End-to-end:** rendering and switching content type, embedding an uploaded SVG
  logo as a `data:` URL with error correction set to `H`, removing the logo,
  rejecting unsupported file types, stepping through every drawable logo size
  without blanking the preview, PNG/SVG export, raising an error on low contrast,
  and verifying QR/Wi-Fi content is never sent over the network.
- **Scannability:** every drawable logo size at every error-correction level is
  exported through the UI and decoded with jsQR, so a size that fails to scan
  fails the build.

## Releasing

Releases are driven by tags. The tag must match the `version` in
`package.json` (the workflow fails otherwise, so the two can't drift).

1. Set `"version"` in `package.json` (e.g. `0.2.1`) and commit it on `main`.
2. Tag and push:

   ```bash
   git tag v0.2.1
   git push origin v0.2.1
   ```

The [release workflow](./.github/workflows/release.yml) then re-runs the full
test suite, builds `dist/`, and publishes a GitHub Release named after the tag
with generated notes and `qr-code-generator-<version>.zip` attached. Unzip it and
serve the contents as a static site.

## Project structure

```
index.html               # Vite entry point; prerendered markup + SEO metadata
public/                  # Static files Vite copies to dist/ verbatim
  robots.txt             # Crawler rules (AI/answer-engine bots explicitly allowed)
  sitemap.xml            # Canonical URL list
  llms.txt               # Plain-text summary for LLM tooling
  favicon.svg            # Site icon
  og.png                 # Open Graph share image, generated by `npm run og`
scripts/
  generate-og.mjs        # Renders public/og.png (real QR, "QR" in the centre)
src/
  main.ts                # UI wiring, QR rendering, PNG/SVG export
  payloads.ts            # QR payload builders, escaping, validation
  contrast.ts            # WCAG contrast ratio and the foreground/background check
  logo.ts                # Logo type/size validation, safe sizing, data-URL reading
  qr.ts                  # Quiet-zone maths (four modules at any render size)
  types.ts               # Shared State and ContentType types
  style.css              # App styles
tests/
  unit/                  # Vitest tests + shared state factory
  e2e/                   # Playwright specs and fixtures
Containerfile.test       # Test/CI image
compose.yaml             # Podman Compose dev service
.github/workflows/ci.yml # GitHub Actions CI workflow
.github/workflows/release.yml # Tag-driven release workflow
```
